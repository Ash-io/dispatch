Run collections from the command line

Run the same collections in a terminal or in CI, with reports and a proper exit code.

Your tests shouldn't only run when you click a button. The Dispatch command line runs your collections in a terminal, or in CI, on every push.

  1. Run a collection

    dispatch run payments.json -e sandbox.json. From the repo: node bin/dispatch.mjs, or npm link once.

    Point the runner at a collection file and an environment. It uses the same runner and scripts as the app, so results match exactly.

  2. Pick folders, iterations and data

    --folder, -n, -d data.csv, --env-var key=value. See --help.

    Run just one folder, repeat it, feed it a data file, or override variables. Everything you can do in the app is here. Run with help to see every option.

  3. Failures fail the build

    Any failure exits with code 1. --bail stops at the first one. -r junit writes a report.

    If anything fails, it exits with code one, so your CI build fails too. Bail stops at the first failure, and the JUnit reporter writes a report your CI can show.

  4. Add it to CI

    Secrets come from CI variables with --vault-from-env. Works on folders saved with Save to a folder (Git).

    In CI, add one step. Vault secrets can come from your CI's secret variables, and it runs folders saved from Dispatch straight from your repository.

Now your API is checked on every push. Next, a shared Dispatch server for your whole team.
