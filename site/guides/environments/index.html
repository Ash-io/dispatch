Environments and variables

Write a request once, then point it at sandbox or production with one switch.

Hard-coding addresses and keys gets messy fast. With environments and variables, you write a request once and run it anywhere.

  1. Open an environment

    Environments tab, then pick one. Each variable has a shared and a current value.

    Go to the Environments tab and open Sandbox. Every variable has a shared value, which syncs with your team, and a current value, which stays on your computer.

  2. Mark secrets as secret

    Set the type to secret and the value is masked on screen.

    For anything sensitive, set the type to secret. The value gets masked, so nobody sees it over your shoulder.

  3. Choose the active environment

    Use the menu at the top right. Every request now uses its values.

    Now choose the active environment from the menu at the top right. Every request will use its values.

  4. Use {{variables}}

    Write {{name}} anywhere. Green means defined, red means missing.

    Write a variable name in double curly braces, in the URL, headers, body or auth. Green means it has a value. Red means it is not defined yet.

  5. Quick look

    The eye button shows every variable in play, and where it comes from.

    To check what is set, click the eye button. It shows every variable in play right now, with its value.

  6. Dynamic variables

    {{$guid}}, {{$timestamp}}, {{$randomEmail}} give a fresh value every send.

    There are also dynamic variables. {{$guid}}, {{$timestamp}} and {{$randomEmail}} give you a fresh value every time you send.

Now one request works in every environment. Next, we will keep your real secrets safe in the Vault.
