Connect Postman and give your team access

Add Postman API keys, invite people with roles, and decide who reaches which workspace.

With the server running, let's connect a Postman account, invite the team, and decide who can see and change what.

  1. Add a Postman API key

    Postman accounts › Add. The key is checked, encrypted, and never shown again.

    In Postman accounts, click Add, and paste a Postman API key. The server checks it with Postman, encrypts it, and never shows it again. Only the last four characters.

  2. See every workspace

    Workspaces lists everything your keys reach. Add more keys for more workspaces.

    The Workspaces tab lists every workspace your keys can reach. You can connect more than one Postman account, and each workspace is listed once.

  3. Add people with a role

    Viewer reads · Editor changes · Creator adds collections · Admin does everything.

    Now add a teammate. Pick a role. Viewers can only read, editors can change things, creators can also add collections, and admins can do everything, including deletes.

  4. Choose their workspaces

    New people start with no workspaces. Tick the ones they need.

    New people start with no workspaces at all, so nothing leaks by accident. Tick just the ones they need, and save.

  5. Or grant from a workspace

    On any workspace: Manage access, then tick people.

    You can also work the other way round. Open a workspace, click Manage access, and tick who should have it.

  6. What the server enforces

    Viewers never get secret current values. Deletes are admin-only. Every call is audited.

    Behind the scenes, the server enforces it all. Viewers never receive secret values, only admins can delete, and every call is written to the audit log.

Your team now works in the right workspaces, with the right permissions, and no Postman accounts of their own. Next: workspaces stored on the server itself.
