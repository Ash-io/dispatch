Authorization: tokens, keys and OAuth 2.0

Set auth once for a whole collection, or override it on a single request.

Most APIs want to know who you are. Let's set up authorisation once, and let every request use it.

  1. Set auth on the collection

    Collection ⋯ › Settings, auth & variables › Authorization.

    The best place for auth is the collection. Open its settings, go to Authorisation, and choose the type. Here, it's a bearer token from a variable.

  2. Requests inherit it

    A request set to Inherit from parent uses the collection's auth.

    Now open any request inside. Its auth is set to inherit from parent, so it uses the collection token automatically.

  3. Override on one request

    Pick another type here: API Key, Basic, Digest, AWS Signature, Hawk…

    Need something different for one request? Pick another type. API key, basic, digest, AWS signature and Hawk are all here, computed just like Postman.

  4. OAuth 2.0

    Fill in the grant, then Get new access token. Authorization code opens a real sign-in window, with PKCE.

    For OAuth 2.0, choose the grant type, fill in the URLs and client details, then click Get new access token. The authorisation code flow opens a real sign-in window.

Auth set once, used everywhere. Next, we will write scripts and tests that run around each request.
