Leave Postman: workspaces on your server

Create workspaces stored on the Dispatch server itself, or copy your Postman workspaces over.

Moving your team off Postman completely? A Dispatch server can store workspaces itself. Create new ones, or copy your existing Postman workspaces across.

  1. Create a workspace here

    Workspaces › New workspace. It lives in the server's own database.

    In Workspaces, click New workspace, and give it a name. It is stored in the server's own database. No Postman account needed.

  2. Copy a Postman workspace over

    Copy to server on any Postman workspace: collections, environments and globals.

    To bring existing work over, click Copy to server on a Postman workspace. Its collections, environments and global variables are copied in one go.

  3. A one-time copy

    Postman is left as it was. The two don't sync afterwards.

    It's a one-time copy. Postman is left as it was, and the two don't sync afterwards. Your team just switches over.

  4. Same app, same rules

    Grant it like any workspace. Roles, redaction and the audit log apply the same way.

    Grant these workspaces like any other. Roles, hidden secrets and the audit log all work the same, and the desktop app uses them exactly like Postman ones.

  5. Back it up

    The data lives only in the server's database. Back up DB_PATH, or wrangler d1 export.

    One important thing: this data lives only in your server's database. So back it up regularly, like any other database.

Your team's work now lives on your own server. Last guide: connecting the desktop app to it, and reading the audit log.
